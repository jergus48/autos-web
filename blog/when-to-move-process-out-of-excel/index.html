When to move a business process out of Excel

24 November 2026 · 5 min read · spreadsheets, excel, planning

Move a process out of Excel when several people need to change it at once, when mistakes in it reach customers or the accounts, or when the work depends on someone remembering to update it. If one person uses the file for analysis or a simple list, leave it where it is.

What is Excel good at?

Excel is hard to beat for some jobs, and replacing it there is a waste of money:

  • One-off analysis, such as comparing supplier prices or planning a budget.
  • Calculations that change often, where the person using them also wants to adjust the formulas.
  • Small lists with one owner, like a register of company phones or a holiday plan for five people.
  • Trying out a process, before you know what the final version should look like.

The last point matters. If you are still changing the columns every week, a spreadsheet is the cheapest place to learn what you need. Building a tool too early only fixes the wrong process in place.

What are the signs that a spreadsheet has become a problem?

One of these alone may be manageable. Two or three together usually mean the file is doing a job it was not made for.

  • There are several versions. Names like "orders final 2 new" show that people no longer know which copy is right.
  • People copy from it into other systems. The order is typed into the spreadsheet, then the accounting program, then an email to the warehouse.
  • Status is tracked by colour. Yellow means waiting, green means paid, and only two people know what orange means. Colour is also easy to lose when someone copies a row.
  • You cannot say who changed what. When a price is wrong, nobody can find out when it happened.
  • Everyone can see everything. Customer details, salaries or margins sit in the same file as the information all staff need.
  • Only one person dares to touch the formulas. If they are away, the process waits.

What goes wrong if you leave it?

Usually nothing dramatic, which is why it stays. A workshop misses a changed measurement because it printed yesterday's copy. A clinic books two people into one slot. A wholesaler invoices the old price because the new list was saved in another folder.

Each case is fixed with a phone call and an apology. The cost is spread across many small moments, so nobody adds it up. If you want to, our post on signs your team spends too long on data entry is a useful place to begin.

There is a data protection side too. A file with personal data that gets emailed around is hard to control: you may not know who holds a copy, or be able to delete a person's details everywhere when you should.

Can you fix the spreadsheet instead?

Often, yes, and it is worth trying first. A few changes solve a surprising share of the trouble:

  1. Keep one shared copy online. Excel through Microsoft 365 and Google Sheets both allow several people to edit the same file and keep a version history.
  2. Replace colours with a status column that uses a fixed dropdown list.
  3. Add validation so a date field accepts only dates and a quantity cannot be text.
  4. Protect the formula cells against accidental typing.
  5. Give each file an owner and write down, on the first sheet, what it is for.

Use the improved file for a month. If the problems are gone, you have saved yourself a project.

What are the options if a spreadsheet is no longer enough?

There are three main routes, and the right one depends on how unusual your process is.

Connect the spreadsheet to other tools. If the file itself works and the pain is copying data in or out, an automation can do that part. New orders arrive as rows, finished rows become invoices, and a message goes out when a status changes. Staff keep the screen they know.

Use a ready-made program. For common needs such as customer records, bookings, stock or time tracking, a standard product is usually the sensible choice. Expect to change some habits to fit it.

Build a small custom tool. This makes sense when your process is specific and the ready-made options need too many workarounds. One example from our own work is a structural calculation app that produces a tailored Word report. It does one job, for people who know exactly what that job is.

A custom tool also has to be maintained, so it should replace a process that is stable and important. If you only need a better list, it is the wrong answer.

How do you move without stopping the work?

The risky version is to switch everything on a Monday morning. A calmer order looks like this:

  • Write down what the file does. Include the unofficial parts: who looks at it, what the notes mean, which sheet feeds which report.
  • Clean the data first. Remove duplicates, agree one spelling for each customer and archive old rows.
  • Move one part. Start with the piece that causes the most errors, such as order intake, and leave the rest alone.
  • Run both for a short time. Compare results, then set an end date. Without one, people will keep two systems forever.
  • Make the old file read-only. Keep it for reference, but close the way back.
  • Keep an export. Whatever you choose, make sure you can get your data out again, ideally as an ordinary spreadsheet.

How do you decide?

Ask three questions. Do several people depend on this file every day? Does a mistake in it cost money or reach a customer? Is the process stable enough to describe on one page?

If all three answers are yes, it is probably time to move. If the first two are yes and the third is no, sort out the process first. If the first two are no, keep the spreadsheet and spend the money elsewhere.
